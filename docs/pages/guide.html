Guide

This guide covers the main Node.js APIs. See the API reference for signatures and options and compatibility for known differences from ExcelJS 4.4.0.

JavaScript snippets below use CommonJS. Put snippets containing await inside an async function, as shown in the complete getting-started example. Handle rejected promises in your application.

Install

npm install exceljs-rs

Requirements: Node.js 22 or later. npm installs a prebuilt binary for your platform:

OSArchitectures
Linux (glibc)x64, arm64
macOSx64, arm64 (Apple silicon)
Windowsx64

Other platforms, including Alpine Linux (musl), have no prebuilt package and are not tested by the release workflow. To attempt a source build, see CONTRIBUTING.md.

Moving from ExcelJS

Start by changing the package import, then run your tests and compare representative workbooks:

// before
const ExcelJS = require('exceljs');
// after
const ExcelJS = require('exceljs-rs');
  • Workbooks, worksheets, rows, cells, styles, formulas, merges, tables, images, data validation, conditional formatting, defined names and worksheet protection target the ExcelJS 4.4.0 API.
  • Compatibility tests compare fixture values and styles. They cannot cover every workbook or application.
  • The differences are fixed ExcelJS bugs and a few engine details, all listed on the compatibility page. Check it if your code relies on an ExcelJS quirk.
  • The browser bundle (exceljs/dist/exceljs.min.js) has no equivalent: exceljs-rs is a native Node.js addon.

Read and write workbooks

const ExcelJS = require('exceljs-rs');

// From a file, a Buffer or a stream
const workbook = new ExcelJS.Workbook();
await workbook.xlsx.readFile('in.xlsx');
// await workbook.xlsx.load(buffer);
// await workbook.xlsx.read(readableStream);

workbook.eachSheet(sheet => {
  sheet.eachRow((row, rowNumber) => {
    console.log(rowNumber, row.values);
  });
});

// To a file, a Buffer or a stream
await workbook.xlsx.writeFile('out.xlsx');
const buffer = await workbook.xlsx.writeBuffer();

Build a workbook

const book = new ExcelJS.Workbook();
const ws = book.addWorksheet('Sales', {views: [{state: 'frozen', ySplit: 1}]});
ws.columns = [
  {header: 'Date', key: 'date', width: 12, style: {numFmt: 'yyyy-mm-dd'}},
  {header: 'Region', key: 'region', width: 16},
  {header: 'Amount', key: 'amount', width: 14, style: {numFmt: '#,##0.00'}},
];
ws.addRow({date: new Date(), region: 'North', amount: 1250.5});
ws.getRow(1).font = {bold: true};
ws.getCell('D2').value = {formula: 'C2*1.2', result: 1500.6};

await book.xlsx.writeFile('sales.xlsx');

Large files: streaming

workbook.xlsx.readFile and writeBuffer hold the whole workbook as objects, one per cell. Use streaming APIs when you can process rows incrementally:

// Write: rows are rendered and compressed as you commit them
const writer = new ExcelJS.stream.xlsx.WorkbookWriter({
  filename: 'big.xlsx',
  useSharedStrings: false, // smaller memory for mostly-unique text
});
const out = writer.addWorksheet('Data');
for (let i = 0; i < 100_000; i++) {
  out.addRow([i, `row ${i}`, new Date()]).commit();
}
await writer.commit();

// Read: one row at a time
const reader = new ExcelJS.stream.xlsx.WorkbookReader('big.xlsx', {
  sharedStrings: 'cache',
  worksheets: 'emit',
});
for await (const worksheet of reader) {
  for await (const row of worksheet) {
    // row.number, row.values, row.getCell(1).value
  }
}

The streaming reader reads its input to the end before it parses, so the compressed file is held in memory (it is usually a fraction of the sheet's size). Each worksheet is then parsed in batches, but shared strings, styles, and other metadata still consume memory. Keep each worksheet within Excel's 1,048,576-row limit.

Controlled reads and bulk data

const controller = new AbortController();
const workbook = new ExcelJS.Workbook();
await workbook.xlsx.readFile('input.xlsx', {
  signal: controller.signal,
  limits: {maxInputBytes: 50 * 1024 * 1024, maxInflatedBytes: 250 * 1024 * 1024,
    maxEntryBytes: 100 * 1024 * 1024, maxCells: 1_000_000, maxMergeCells: 1_000_000},
  onProgress: progress => console.log(progress.phase, progress.rows),
});

async function* records() {
  for (let i = 0; i < 100_000; i++) yield [i, `row ${i}`];
}
const writer = new ExcelJS.stream.xlsx.WorkbookWriter({filename: 'bulk.xlsx'});
const sheet = writer.addWorksheet('Data');
const count = await writer.writeRows(sheet, records(), {
  batchSize: 128, signal: controller.signal,
});
sheet.commit();
await writer.commit();

for await (const {worksheet, rows} of ExcelJS.stream.xlsx.readBatches('bulk.xlsx', {
  batchSize: 1000, signal: controller.signal, limits: {maxCells: 1_000_000},
})) {
  console.log(worksheet.name, rows[0].number, rows[0].values[1]);
}

Bulk export waits for slow destinations between batches. Finish worksheets in creation order. Batch import avoids Workbook, Row, and Cell objects; values have one-based sparse indices, and empty sheets produce no batches. Compressed input, shared strings, and metadata still occupy memory. Limits are optional, inclusive, and validated; cancellation and progress callback failures clean up native readers. See the full controls and ownership contract before selecting resource bounds.

CSV

const workbook = new ExcelJS.Workbook();
const sheet = await workbook.csv.readFile('data.csv', {
  parserOptions: {delimiter: ';'},
});
await workbook.csv.writeFile('out.csv', {formatterOptions: {delimiter: ','}});

Options are those of ExcelJS (parserOptions, formatterOptions, dateFormats, map, includeEmptyRows). Input is parsed chunk by chunk as it arrives.

Formulas are stored with optional cached results; exceljs-rs does not calculate them. Worksheet protection restricts editing and does not encrypt files.

TypeScript

Type definitions are included, with the same names as ExcelJS's. They check under strict with nodenext or bundler module resolution.

Install @types/node in TypeScript projects.

import * as ExcelJS from 'exceljs-rs';

const workbook: ExcelJS.Workbook = new ExcelJS.Workbook();
const sheet: ExcelJS.Worksheet = workbook.addWorksheet('Data');
const cell: ExcelJS.Cell = sheet.getCell('A1');

Untrusted files

Neither streaming nor an upload-size limit prevents resource exhaustion. Parse untrusted files in a separate process with memory and time limits. CSV quoting does not prevent formula injection when exported data is opened in a spreadsheet application. Read the security guidance.
