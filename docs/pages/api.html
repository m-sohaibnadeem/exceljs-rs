API reference

The package exports Workbook, stream.xlsx.WorkbookWriter, stream.xlsx.WorkbookReader, and value enums. The TypeScript declarations describe the available types. This page covers the main application APIs; the guide provides examples.

Worksheet, row, and cell objects come from a workbook; they are not top-level constructors. Rows and columns use one-based indices. Worksheet IDs are not array positions and can have gaps after deletion.

cell.value accepts null, strings, numbers, booleans, Date values, or structured values:

cell.value = {formula: 'SUM(B2:B10)', result: 42};
cell.value = {text: 'Project', hyperlink: 'https://example.com'};
cell.value = {richText: [{text: 'Total', font: {bold: true}}]};
cell.value = {error: '#N/A'};

Formula results are cached values supplied by the caller or read from a file. exceljs-rs does not calculate formulas. row.values is a sparse, one-based array when read; index 0 is unused.

Styles and worksheet features

sheet.getCell('B2').numFmt = '#,##0.00';
sheet.getRow(1).font = {bold: true};
sheet.getCell('A1').alignment = {vertical: 'middle', horizontal: 'center'};
sheet.getCell('A1').fill = {
  type: 'pattern', pattern: 'solid', fgColor: {argb: 'FFE8F0FE'},
};
sheet.views = [{state: 'frozen', ySplit: 1}];
sheet.autoFilter = 'A1:B10';

Colors use eight-digit ARGB strings. Style objects can be shared between cells; clone a style before changing it when cells should have independent styles.

Other worksheet APIs include addTable(options), addConditionalFormatting(options), cell.dataValidation, cell.note, and protect(password, options). Add images with workbook.addImage({buffer, extension}) and sheet.addImage(imageId, range). Images require an in-memory workbook. Protection is not encryption.

XLSX I/O

All methods below are asynchronous. Await completion and handle rejection.

APIInput or result
workbook.xlsx.readFile(path, options?)Read a file into the workbook; resolves to that workbook.
workbook.xlsx.load(data, options?)Load a Buffer, Uint8Array, or ArrayBuffer; resolves to the workbook.
workbook.xlsx.read(readable, options?)Buffer a readable stream, then load it.
workbook.xlsx.writeFile(path, options?)Write a file.
workbook.xlsx.writeBuffer(options?)Resolve to a Node.js Buffer containing the ZIP archive.
workbook.xlsx.write(writable, options?)Build the archive in memory, then write it to the destination.

Read options include ignoreNodes (worksheet XML element names), maxRows, maxCols, and base64 for encoded string input. Row and column limits do not bound decompression or total memory use. A failed load can leave a partially loaded workbook; discard it after an error.

Write options include useSharedStrings and zip: {compressionOptions: {level: 6}}. The Rust engine handles compression; options for other ZIP libraries are not a promise of equivalent behavior.

CSV I/O

workbook.csv.readFile(path, options?) and read(readable, options?) resolve to the loaded worksheet. writeFile(path, options?), write(writable, options?), and writeBuffer(options?) export a worksheet.

Read options include sheetName, parserOptions, dateFormats, and map(value, index). Write options include sheetName, sheetId, formatterOptions, dateFormat, dateUTC, includeEmptyRows, and map(value, index). Use delimiter within parser or formatter options. CSV does not preserve workbook formatting, formulas, multiple sheets, or value types.

Streaming

new stream.xlsx.WorkbookWriter({filename, useStyles, useSharedStrings}) writes to a file. Use stream instead of filename to supply a writable destination. Styles and shared strings are disabled by default. Call row.commit() when a row is complete, then await writer.commit(). Committed rows cannot be edited. Shared strings can grow with the number of distinct values.

new stream.xlsx.WorkbookReader(input, options?) accepts a file path or readable stream. Iterate over worksheets and rows with for await. Defaults: worksheets emit, shared strings cache, hyperlinks ignore, styles ignore, and entries ignore. Set styles: 'cache' when cell styles or date interpretation are needed.

The streaming reader holds compressed input in memory before parsing. Streaming APIs have a narrower editing surface than the in-memory workbook. See the known limitations and security guidance.

Large-file extensions

These APIs are optional additions to the ExcelJS surface. XLSX load, read, readFile, WorkbookReader, and readBatches accept limits, signal, and onProgress.

LimitInclusive bound
maxInputBytesCompressed input bytes.
maxZipEntriesZIP entries, including directories and duplicates.
maxEntryBytes, maxInflatedBytesActual inflated bytes per entry and across all entries.
maxCells, maxSharedStringsRaw worksheet cell elements and shared-string items.
maxTokenBytesBytes per raw XML tag, comment, CDATA section, declaration, or contiguous text run.
maxValidationCells, maxMergeCellsCells covered by validation and merge declarations, including repeated ranges and merge masters.

Limits accept nonnegative safe integers; zero is a real bound. Controlled reads preflight every entry once, including unknown, media, and ignored parts, using actual decompression reads. Parsing passes are uncharged. Compressed input remains buffered. Progress reports monotonic inputBytes, inflatedBytes, entries, cells, sharedStrings, validationCells, mergeCells, and rows, with phases input, archive, rows, merges, and done. Parsed rows may lead delivered rows.

writer.writeRows(worksheet, iterable, options?) resolves to the number of rows written. It accepts arrays or keyed objects from a sync or async iterable. Options: positive integer batchSize (default 128), signal, and onProgress({phase, rows}) (phases rows and done). Rows commit synchronously; the helper checkpoints compression and waits for destination drain before pulling more rows. Finish each worksheet in creation order, then await writer.commit(). Foreign or committed sheets and overlapping operations reject. One huge row, styles, and shared strings can still consume substantial memory; in-memory output retains the archive.

stream.xlsx.readBatches(input, options?) is an async generator yielding {worksheet: {id, name}, rows: [{number, values}]}. It accepts filenames, readable streams, Buffer, ArrayBuffer, typed arrays, and DataView. batchSize defaults to 1000 and must be a positive safe integer. Batches follow workbook order, contain one sheet and at most batchSize rows, and omit empty sheets. Values are sparse and one-based, preserving dates, cached formulas, rich text, errors, and hyperlinks. Styles and merge slaves are omitted. It supports maxRows, maxCols, and ignoreNodes; base64 is unsupported.

Cancellation preserves signal.reason and cooperatively stops native parsing. Callback exceptions reject and clean up. Early exit from batch iteration closes native cursors. Caller-owned streams stay open on abort; owned file streams close. Read failures can leave partial workbook state. Bulk failures leave the writer unusable and make commit reject with the original reason. Source iterator return() is requested without waiting for an uncooperative source. Consume controlled WorkbookReader worksheets inside the outer iteration.
