Benchmarks

Historical measurements supplied with the project. Raw result logs and a source revision were not recorded, so these numbers are illustrative and are not verified release guarantees. Run the commands below to measure your build.

The same workloads run with ExcelJS 4.4.0 and with excel-rs: 100,000 rows × 6 columns (numbers, strings, dates, booleans and formulas). Each workload runs in a fresh process per library, and the best of 3 runs is reported. The read workloads read every cell's value. Peak memory is the process's high-water mark (RSS).

Setup: Node.js 22, Linux, 4-core 2.1 GHz Xeon. Numbers vary with hardware; reproduce them on yours.

Where the time goes

Whole-workbook readFile and writeBuffer keep the whole sheet as JavaScript objects, with a Row, a Cell and a value object per cell, so that the API behaves as ExcelJS's does. Building those objects costs about the same in both libraries, so it bounds the speed-up. Everything below it (ZIP, XML, styles, shared strings) runs in Rust. Writers compress on a thread of their own while they render, and rows cross into JavaScript in batches, in a binary format. For the largest files, use the streaming reader and writer.

cd excel-rs/crates/excel-rs-node
npm ci && npm run build        # release build of the addon
